# Phase 2 Wave B 조사 결과 — 발전사 계약현황 odcloud API (2026-07-14)

`scripts/probe_odcloud_contracts.py`를 GitHub Actions probe 모드(run #191,
job 87007922417)에서 실행한 결과. data.go.kr 본 포털은 해외 IP를 차단하지만
**api.odcloud.kr(파일데이터 자동변환 오픈API)는 러너에서 정상 응답**한다.
인증키는 `G2B_API_KEY`(data.go.kr 일반 인증키) 재사용.

## 배경 — 왜 필요한가

발전 5사(KOSPO·EWP·KOMIPO·KOEN·KOSEP 등)의 **자체 계약(발전소 건설·경상정비)**
상당수가 나라장터(G2B) 밖에서 체결돼 조달청 OpenAPI로는 회수되지 않는다.
검증 표본: 동서발전 **음성 천연가스 발전소 송전선로 건설 공사**(2021-04-12,
계약금액 1,050억 / 예정가격 1,200억)는 G2B 수집분에 없으나 EWP 자체
계약현황에는 존재 → **커버리지 갭 확정**.

## KOSPO (한국남부발전) — 계약 체결 현황

- 데이터셋 ID `15095366`, 연도별 uddi 5개(2021~2025 파일).
- **필드**: `계약금액 · 계약명 · 계약일자 · 구분 · 사업소 · 일련번호`
  - `구분` = `구매입찰정보` / `공사용역입찰정보` (조달유형 대용)
  - **예정가격 필드 없음** — 100억 판정은 계약금액 단독.
  - 계약금액 타입 혼재(문자열/숫자) → 파싱 시 정규화 필요.
- **커버리지**: 각 연도 파일이 **누적본**(항상 2020-01-02 시작).
  - 2021 파일 → 2020-01-02 ~ 2021-06-30 (1,643행)
  - 2025 파일 → 2020-01-02 ~ 2025-06-30 (4,979행) ← 최신·최대
  - **상반기 스냅샷**(매년 6월 말까지). 하반기분은 익년 파일에 반영 추정.
  - ⇒ 수집 시 **최신 연도 파일 1개만** 받으면 2020~직전 상반기 전량 확보.
- 100억↑(계약금액 기준) 예시: 신세종복합 발전소 건설공사 1,610억,
  신인천 연료전지 4단계 LTSA 552억, 2019~2020 발전설비 경상정비 712억 등.

## EWP (한국동서발전) — 공사·용역·물품 계약현황

- 데이터셋 ID `15065323`, 2025 uddi 1개 확인.
- **필드(11개, KOSPO보다 풍부)**: `계약금액(부가세 포함) · 예정가격(부가세 포함)
  · 계약명 · 계약방법 · 계약번호 · 계약업체 · 계약일자 · 구분 · 담당사업소 ·
  소재지 · 조달유형`
  - `구분` = 공사/용역/물품, `조달유형` = 전자입찰/제한경쟁 등, `계약번호` 존재
    → **G2B 대비 dedup 키로 활용 가능**.
- **커버리지**: 2025 파일이 **2016-01-04 ~ 2025-06-30 (8,315행)** — 深이 깊은
  누적본. 역시 상반기 스냅샷.
- 100억↑ 예시: **음성 천연가스 발전소 송전선로 건설공사 1,050억**,
  음성천연가스발전소 연료공급시설 277억, 울산복합 2,3CC 경상정비 200억,
  당진화력 3,4호기 터빈·보일러 경상정비 223억 등. 음성 관련 공사만 15+건.

## 구현 (2026-07-16) — 정식 어댑터화 완료

조사 결과를 `src/adapters/genco_odcloud.py`의 **`OdcloudContractsMixin`**으로
정식 통합했다. genco 어댑터(kepco_family.py)에서 이 믹스인을 KEPCOAdapter보다
앞에 상속(KOSPO·EWP)해 **공고는 KEPCO 빅데이터, 계약은 odcloud**로 이원화한다.

- **`ODCLOUD_DATASETS`**: source→{연도:uddi} 매핑. `_odcloud_path()`가 최신 연도
  (누적 최다)를 자동 선택. 신규 연도 스냅샷 공개 시 이 dict에 한 줄 추가.
- **`fetch_contracts(since, until)`**: 최신 누적 스냅샷을 전량 순회 후 계약일자로
  기간 필터. 429/5xx는 http_client 재시도. G2B_API_KEY 미설정 시 계약만 skip.
- **`is_large_construction_contract`**: 공사 + 계약금액 100억↑ (EX 어댑터와 동일
  규약). EWP는 구분=='공사', KOSPO는 계약명 휴리스틱(`_odcloud_is_construction`).
- **`normalize_contract`**: 공통 contracts 스키마로 매핑(EWP는 계약번호·계약업체·
  계약방법까지, KOSPO는 금액·사업소 위주). run_monthly `_is_target_contract`가
  최종 100억↑ 공사 게이트를 건다.
- 테스트 `tests/test_genco_odcloud.py`(공사판별·필터·정규화·페이징·기간필터·키부재)
  + run_monthly 통합 구동으로 음성 송전선로 1,050억이 DB/CSV까지 도달 확인.

| **KOEN(남동)** | ✅ 대규모 공사 정보 fileData `15040187` | 사용자 페이지 확인/uddi 대기 |

**KOMIPO 활용신청 필요**: probe(run #197)에서 15003748이 **HTTP 401**을 반환.
KOSPO(15095366)·EWP(15065323)는 G2B_API_KEY 계정에 활용신청돼 있으나 15003748은
미신청. odcloud 자동변환 API는 **데이터셋별 활용신청**이 필요하다
(data.go.kr 15003748 페이지 '활용신청' 버튼, 보통 즉시 승인). 승인 시 코드 변경
없이 즉시 동작 — 어댑터는 미승인 시 401을 흡수해 계약 0건으로 스킵(공고는 정상).

### 잔여 과제

- **KOMIPO 활용신청 승인 후** 라이브 수집으로 필드·구분값·100억 공사 재검증
  (현재 공사 판별은 계약명 휴리스틱, 실데이터로 tightening 예정).
- **KOEN(남동, 15040187)** odcloud uddi 확보 시 동일 패턴으로 등록.
- **dedup**: EWP 계약번호·계약업체로 G2B 계약과 교차 판정 가능(현재 발전사 자체
  계약은 G2B에 없어 실질 중복 없음). 향후 G2B 통합 집계 시 계약명+일자+금액 보조키.
- **스냅샷 갱신 감지**: 상반기 스냅샷이라 신규 연도 uddi를 수동 추가해야 함 —
  데이터셋 목록 API로 최신 uddi 자동 발견하는 후속 개선 여지.
